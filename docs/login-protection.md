# BuildWorld 登录保护与公网启用前检查

本地源码支持持久化登录限流和按用户配置的 TOTP；默认不强制 TOTP。未配置并验证以下保护前，不应将密码登录直接暴露到公网。

在现有配置的 `auth` 节点合并下列字段，为每个需要密码登录的账号单独生成不少于 16 字节随机数，使用 Base32 编码，并通过可信方式录入验证器；示意值不是可用密钥：

```yaml
auth:
  totp_required: true
  totp_secrets:
    <用户名>: <该用户独立的Base32密钥>
```

启用后要求密码和六位 TOTP，保护普通浏览器和 JWT 会话；启用前签发的非 MFA 会话不再通过。机器 API token 仍是独立身份，应按现有权限机制限制、轮换并审计。每个动态验证码只能消费一次，登录限流和已消费验证码记录保存在原审计数据库内；保留该数据库和备份。`/api/version` 的 `auth_totp_required` 为 `true` 只表示配置已启用，仍需验证真实登录和拒绝错误、重复验证码。

每账号 5 分钟最多 10 次密码登录尝试，每个实际连接来源 5 分钟最多 60 次；失败和成功都计入。代理后的连接可能共享来源配额，投产前需压测并核对代理网络拓扑；不会信任客户端伪造的转发头。审计记录持续增长，需要纳入既有数据库容量和保留策略。

密钥应通过受控流程配置、备份和轮换。配置生效后，轮换或删除该用户的 TOTP 密钥会使其旧 MFA 会话失效；已有 API token 是独立身份，仍需按需要单独撤销。丢失验证器时通过受控管理员流程恢复，不降低全局 MFA 配置。

公网启用还需完成 TLS、受控反向代理、源站不可绕过、域名解析、WebSocket 与下载、机器身份及真实浏览器验证。此文件不代表这些条件已经部署或验收。
