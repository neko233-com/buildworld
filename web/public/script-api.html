Script API

用于项目构建配置的 TypeScript 声明式 API。此页不在默认导航中，但可通过 /script-api.html 直接打开。

设计目标：获得 Jenkinsfile 的编排表达力，同时保持可校验、可审计的配置边界。源码由 TypeScript AST 白名单解析器读取，只构造 Pipeline 数据；配置解析阶段不执行 JavaScript，也不提供 Node.js、文件系统、网络或进程能力。

最小示例

import { definePipeline, shell, stage } from '@buildworld/pipeline'

export default definePipeline({
  name: 'Deploy service',
  stages: [
    stage('Build', shell('Compile', 'npm run build')),
    stage('Deploy', shell('Upload', './deploy.sh')),
  ],
})

Jenkins tail -f 的安全替代

watchService 只观察服务，不拥有或终止服务进程。它会自动把 Pipeline 视为长期运行；显式 timeoutSec 仍然生效。日志使用独立的近实时节奏持续跟随并在积压时立即追赶，不受 PID 轮询间隔限制；日志缺失、截断或轮转后会按路径恢复，默认每 30 秒输出心跳。PID 消失时输出最后 50 行并使构建失败；取消构建只停止观察。WebSocket 实时输出先发送，SQLite 持久日志按批写入并保留每个构建最新 1,000,000 字符；发生截断时页面和下载内容会显示明确标记。

import { definePipeline, shell, stage, watchService } from '@buildworld/pipeline'

export default definePipeline({
  name: 'Game server',
  stages: [
    stage('Start', shell('Start server', './start-server.sh')),
    stage('Observe', watchService('Live server log', {
      targetDir: '/srv/game-server',
      pidFile: 'game-server.pid.txt',
      logFile: 'server-game.log',
      port: 10101,
      heartbeatSeconds: 30,
      initialLines: 10,
    })),
  ],
})

API

函数用途
definePipeline(config)定义 Pipeline。支持 name、stages、environment、parameters、triggers、allowLongRunning。
stage(name, steps, options?)创建阶段；steps 可传一个步骤或步骤数组。
step(name, type, command, options?)创建显式类型步骤；用于插件或内置步骤的低层声明。
shell(name, command, options?)在受控构建执行器中执行 shell 命令。
script(name, command, options?)将多行 POSIX shell 作为临时脚本执行。
tail(name, command, options?)运行普通 tail 类命令；长期服务监控应使用 watchService。
git(name, options?)声明 Git 步骤。
notify(name, options?)调用 BuildWorld 原生通知服务；远端 Worker 不持有通知凭据时会明确跳过。
watchService(name, options)持续追踪 PID 和日志。pidFile、logFile 必填；initialLines: 0 跳过已有历史。其余选项：targetDir、port、heartbeatSeconds（5–86400）、pollSeconds（1–3600，仅控制 PID 存活检查）、initialLines（0–10000）。日志始终使用独立的近实时跟随与积压追赶。
trigger(type, config?)声明 VCS、定时等构建触发器。
parameter(name, type, options?)声明 string、text、password、choice、boolean 或 number 构建参数。

配置对象

类型字段
Pipelinename、description、environment、parameters、approval、stages、on/triggers、artifacts、post、agentRequirements、retentionCompleted、timeoutSec、allowLongRunning、disableConcurrent、abortPrevious、toolchains。
Stageid、name、steps、parallel、dependsOn、branches、if、environment、workingDirectory、timeoutSec。
Stepname、type、command、shell、config、platformAdditions、runtime、if。
ApprovalPolicyversion、strategy、requiredRoles、allowRequester、prompt。

所有 camelCase 字段均由 SDK 归一化到服务端格式；类型文件也保留对应 snake_case 字段，便于无损读取迁移配置。条件支持 true、false、success()、failure()、always()、!、&&、|| 与括号。

GitHub Actions 风格 YAML

name: verify
jobs:
  build:
    runs-on: [linux, amd64]
    steps:
      - uses: actions/checkout@v4
      - name: Compile
        run: npm run build
  test:
    needs: build
    if: success()
    timeout-minutes: 15
    steps:
      - name: Test
        run: npm test

needs 可为单值或数组；依赖按拓扑顺序执行，循环依赖、未知 job、未知 uses action 和不匹配的 runs-on 会在运行前明确失败。

安全边界

  • 支持：注释、字符串/静态模板字符串、数字、布尔值、对象、数组、声明式 helper 调用、as const 和 satisfies Pipeline。
  • 禁止：eval、Function、动态属性、函数/类、循环、条件表达式、模板插值、定时器、Promise、require 和 process。
  • 只允许从 @buildworld/pipeline 导入。构建命令由步骤执行器处理，不在配置求值时运行。
  • 解析器限制源码大小、AST 节点数、嵌套深度和输出大小；不会因无限循环阻塞控制面。
  • pidFile 与 logFile 必须位于 targetDir 内，防止借日志追踪读取任意路径。

编辑器与 SDK

项目、模板和可视化 Pipeline 页面均使用内置 Monaco TypeScript 编辑器，支持注释、补全、语法/类型诊断和实时服务端 AST 校验。发布包内的 sdk/pipeline/index.d.ts 是人类编辑器与 AI Agent 共用的类型契约。
