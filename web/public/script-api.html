BuildWorld

Script API

用于项目构建配置的 TypeScript 声明式 API。此页不在默认导航中，但可通过 /script-api.html 直接打开。

设计目标：获得 Jenkinsfile 的编排表达力，同时保持可校验、可审计的配置边界。脚本只构造 Pipeline 数据；BuildWorld 不提供 Node.js、文件系统、网络、进程或任意代码执行能力。

最小示例

import { definePipeline, shell, stage } from '@buildworld/pipeline'

export default definePipeline({
  name: 'Deploy service',
  stages: [
    stage('Build', shell('Compile', 'npm run build')),
    stage('Deploy', shell('Upload', './deploy.sh')),
  ],
})

Jenkins tail -f 的安全替代

watchService 只观察服务，不拥有或终止服务进程。构建保持运行并持续输出日志；PID 消失时构建失败；取消构建只停止观察。

import { definePipeline, shell, stage, watchService } from '@buildworld/pipeline'

export default definePipeline({
  name: 'Game server',
  allowLongRunning: true,
  stages: [
    stage('Start', shell('Start server', './start-server.sh')),
    stage('Observe', watchService('Live server log', {
      targetDir: '/srv/game-server',
      pidFile: 'game-server.pid.txt',
      logFile: 'server-game.log',
      port: 10101,
      heartbeatSeconds: 30,
      initialLines: 10,
    })),
  ],
})

API

函数用途
definePipeline(config)定义 Pipeline。支持 name、stages、env、parameters、triggers、allowLongRunning。
stage(name, steps, options?)创建阶段；steps 可传一个步骤或步骤数组。
shell(name, command, options?)在受控构建执行器中执行 shell 命令。
git(name, options?)声明 Git 步骤。
notify(name, options?)声明通知步骤。
watchService(name, options)持续追踪 PID 和日志。选项：targetDir、pidFile、logFile、port、heartbeatSeconds、initialLines。

安全边界

  • 支持：注释、字符串、对象字面量、数组、声明式 API 调用和 as const。
  • 禁止：eval、Function、require、process、循环、函数/类、定时器、Promise 和箭头函数。
  • 只允许从 @buildworld/pipeline 导入。构建命令由步骤执行器处理，不在配置求值时运行。
  • pidFile 与 logFile 必须位于 targetDir 内，防止借日志追踪读取任意路径。
